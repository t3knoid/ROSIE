# Model Configurations

ROSIE uses two llama.cpp servers with OpenAI-compatible endpoints: one for chat completion and one for embeddings. The chat defaults are `LLAMA_CHAT_BASE_URL=http://localhost:8080/v1` and `LLAMA_CHAT_MODEL=local-chat`; embeddings default to `LLAMA_EMBEDDING_BASE_URL=http://localhost:8081/v1` and `LLAMA_EMBEDDING_MODEL=local-embedding`. In Compose, these URLs target the internal `llama-chat` and `llama-embeddings` services. The aliases must match the corresponding server `--alias` values.

The servers load local GGUFs from `LLAMA_MODELS_PATH` (default `./models`). `LLAMA_CHAT_MODEL_FILE` defaults to `Llama-3.2-3B-Instruct-Q4_K_M.gguf`, available from [bartowski's Llama 3.2 3B Instruct GGUF repository](https://huggingface.co/bartowski/Llama-3.2-3B-Instruct-GGUF); `LLAMA_EMBEDDING_MODEL_FILE` defaults to `nomic-embed-text-v1.5.Q4_K_M.gguf`, available from [Nomic's embedding GGUF repository](https://huggingface.co/nomic-ai/nomic-embed-text-v1.5-GGUF). The README includes exact download commands. Review each model card and license before use; the chat model is subject to Meta's Llama 3.2 license terms. The embedding model must support llama.cpp's embedding mode. Compose sets `LLAMA_EMBEDDING_UBATCH_SIZE=1024` by default so passages over 512 tokens can be processed; increase it only if necessary, since larger microbatches use more memory. The Compose deployment uses the CUDA 12 image for Pascal-generation NVIDIA GPUs and reserves the NVIDIA device for both services. `LLAMA_PARALLEL` (default `1`) sets concurrent slots on each server; a single slot reduces peak VRAM use on smaller cards. `LLAMA_N_GPU_LAYERS` (default `99`) controls offloading, while `LLAMA_CTX_SIZE` (default `10240`) controls the chat context size. Chat response latency is also controlled by `CHAT_EVIDENCE_LIMIT` (default `2` passages) and `CHAT_MAX_OUTPUT_TOKENS` (default `512` tokens); reducing these can improve speed at the cost of less context or shorter answers. See the [Tesla P4 GPU operations guide](gpu-acceleration.md) for tuning steps. `RELEVANCE_THRESHOLD` controls the minimum Qdrant cosine similarity returned as evidence. Model quality, memory use, and response time depend on the selected models and host hardware.
